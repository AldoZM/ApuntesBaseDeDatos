\section[InnoDB vs MyISAM]{\emj{⚖️}~InnoDB vs MyISAM}

MySQL históricamente separaba el servidor del motor de almacenamiento.
InnoDB es el motor transaccional; MyISAM es el motor legado sin transacciones.
Desde MySQL 5.5 (2010), InnoDB es el motor por defecto y la elección correcta en la práctica totalidad de los casos.

\begin{teoriabox}{InnoDB vs MyISAM: diferencias clave}
\begin{itemize}
  \item \textbf{InnoDB:} ACID completo, FK enforced, row-level locking, MVCC, crash recovery automático
  \item \textbf{MyISAM:} sin transacciones, sin FK, table-level lock (bloquea toda la tabla por escritura), crash recovery manual
  \item \textbf{Rendimiento:} MyISAM puede ser más rápido en lecturas puras de bulk (sin concurrencia), pero InnoDB supera en cualquier escenario real con escrituras concurrentes
  \item \textbf{Regla práctica:} usa siempre InnoDB. MyISAM solo aparece en sistemas heredados o tablas temporales de solo lectura con volumen extremo.
\end{itemize}
\end{teoriabox}

\section[Diferencias clave con PostgreSQL]{\emj{📋}~Diferencias clave con PostgreSQL}

MySQL y PostgreSQL comparten el estándar SQL pero difieren en sintaxis, semántica y características.
Conocer las diferencias es crítico al migrar entre motores o trabajar en proyectos mixtos.

\begin{itemize}
  \item \texttt{AUTO\_INCREMENT} (MySQL) vs \texttt{SERIAL} / \texttt{GENERATED ALWAYS AS IDENTITY} (PG)
  \item MySQL no tiene \texttt{RETURNING} en \texttt{INSERT}/\texttt{UPDATE}; PostgreSQL sí
  \item \texttt{GROUP BY} en MySQL es más permisivo con \texttt{ONLY\_FULL\_GROUP\_BY} desactivado (comportamiento peligroso)
  \item MySQL usa \texttt{SHOW PROCESSLIST}, \texttt{SHOW STATUS} para monitoreo; PG usa \texttt{pg\_stat\_activity}
  \item Replicación master-replica nativa vía binlog en MySQL; PG usa WAL streaming replication
  \item MySQL tiene \texttt{ON DUPLICATE KEY UPDATE} para upserts; PG usa \texttt{INSERT ... ON CONFLICT}
\end{itemize}

\section[Particionamiento]{\emj{🗂️}~Particionamiento}

El particionamiento divide físicamente una tabla lógica en subtablas según un criterio.
Mejora rendimiento cuando las queries filtran por la columna de partición (partition pruning): el motor lee solo las particiones relevantes.

\begin{tipbox}{Partition Pruning}
Si la columna de partición está en el \texttt{WHERE}, MySQL descarta particiones automáticamente.
\texttt{EXPLAIN} mostrará \texttt{partitions: p2023} en lugar de leer toda la tabla.
Sin la columna de partición en el filtro, se leen \emph{todas} las particiones --- peor que sin particionamiento.
\end{tipbox}

\begin{lstlisting}[caption={Sintaxis MySQL --- diferencias con PostgreSQL}]
-- AUTO_INCREMENT (MySQL) vs SERIAL (PostgreSQL)
CREATE TABLE productos (
    id      INT AUTO_INCREMENT PRIMARY KEY,
    nombre  VARCHAR(100) NOT NULL,
    precio  DECIMAL(10,2)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- UPSERT en MySQL
INSERT INTO clientes (email, nombre, visitas)
VALUES ('ana@ej.com', 'Ana', 1)
ON DUPLICATE KEY UPDATE visitas = visitas + 1;

-- Ver motor de cada tabla
SELECT table_name, engine
FROM   information_schema.tables
WHERE  table_schema = 'mi_base';
\end{lstlisting}

\begin{lstlisting}[caption={Particionamiento por RANGE en MySQL}]
CREATE TABLE ventas (
    id      INT AUTO_INCREMENT,
    fecha   DATE NOT NULL,
    monto   DECIMAL(10,2),
    PRIMARY KEY (id, fecha)
)
PARTITION BY RANGE (YEAR(fecha)) (
    PARTITION p2022 VALUES LESS THAN (2023),
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION p2024 VALUES LESS THAN (2025),
    PARTITION pfuture VALUES LESS THAN MAXVALUE
);

-- Partition pruning automático
EXPLAIN SELECT * FROM ventas
WHERE fecha BETWEEN '2023-01-01' AND '2023-12-31';
\end{lstlisting}

\begin{lstlisting}[caption={Monitoreo y replicación básica}]
-- Ver procesos activos
SHOW PROCESSLIST;

-- Ver estado del servidor
SHOW STATUS LIKE 'Threads%';
SHOW STATUS LIKE 'Innodb_row_lock%';

-- Estado de replicación (en esclavo)
SHOW SLAVE STATUS\G

-- Variables de configuración
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';
SHOW VARIABLES LIKE 'max_connections';
\end{lstlisting}
