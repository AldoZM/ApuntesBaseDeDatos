\chapter{Índices}

\section[¿Qué es un índice?]{\emj{🧠}~¿Qué es un índice?}

Un índice es una estructura de datos auxiliar que mantiene una copia ordenada de uno o más atributos, con punteros a las filas originales.
La analogía es el índice de un libro: en lugar de leer todo el libro para encontrar un tema, saltas directo a la página.
Sin índice, el DBMS hace un \textbf{Seq Scan}: lee cada fila de la tabla. Con índice, hace un \textbf{Index Scan}: O(log n).

\begin{teoriabox}{Costo real de un índice}
Un índice no es gratuito:
\begin{itemize}
  \item \textbf{Espacio en disco:} el índice ocupa espacio adicional (típicamente 10-30\% del tamaño de la tabla)
  \item \textbf{Lentitud en escrituras:} cada \texttt{INSERT}, \texttt{UPDATE} o \texttt{DELETE} debe actualizar todos los índices de la tabla
  \item \textbf{Mantenimiento:} los índices se fragmentan con el tiempo (bloat) y requieren \texttt{REINDEX} periódico
\end{itemize}
El trade-off es: acelera lecturas, penaliza escrituras. En tablas con muchas escrituras y pocas lecturas, un índice puede empeorar el rendimiento.
\end{teoriabox}

\section[Tipos de índices en PostgreSQL]{\emj{🧠}~Tipos de índices en PostgreSQL}

PostgreSQL ofrece varios tipos de índices, cada uno optimizado para un tipo de búsqueda distinto.
B-tree cubre el 90\% de los casos; los demás tipos resuelven necesidades específicas.

\begin{itemize}
  \item \textbf{B-tree:} default. Soporta \texttt{=, <, >, BETWEEN, LIKE 'prefix\%'}. Casi siempre la elección correcta.
  \item \textbf{Hash:} solo igualdad (\texttt{=}). Más rápido que B-tree para igualdad exacta, sin soporte de rango.
  \item \textbf{GIN} (Generalized Inverted Index): búsqueda en arrays, JSONB, full-text search (\texttt{@@} operador).
  \item \textbf{GiST:} datos geométricos, rangos, full-text. Más versátil que GIN pero más lento en búsqueda.
  \item \textbf{BRIN:} tablas muy grandes con datos correlacionados con posición física (series de tiempo, logs).
\end{itemize}

\section[Cuándo crear (y no crear) un índice]{\emj{💡}~Cuándo crear (y no crear) un índice}

El criterio principal para crear un índice es la \textbf{selectividad}: qué fracción de la tabla retorna la condición filtro.
Un índice en una columna booleana con 50/50 de valores no ayuda; el optimizador preferirá Seq Scan de todas formas.

\begin{tipbox}{Reglas prácticas para índices}
\textbf{Crea índice en:}
\begin{itemize}
  \item Columnas en \texttt{WHERE} con alta selectividad y consultas frecuentes
  \item FK --- PostgreSQL \emph{no} las indexa automáticamente, a diferencia de MySQL
  \item Columnas en \texttt{JOIN} y \texttt{ORDER BY} con muchos registros
\end{itemize}
\textbf{No crees índice en:}
\begin{itemize}
  \item Tablas pequeñas (< 1000 filas): Seq Scan es más rápido
  \item Columnas con baja cardinalidad (boolean, status con 3 valores)
  \item Columnas que se actualizan constantemente (costo de mantenimiento supera la ganancia)
\end{itemize}
\end{tipbox}

\begin{lstlisting}[caption={Crear índices B-tree, parcial y compuesto}]
-- Índice simple (B-tree por defecto)
CREATE INDEX idx_empleados_depto ON empleados(id_depto);

-- Índice compuesto
CREATE INDEX idx_pedidos_cliente_fecha ON pedidos(id_cliente, fecha DESC);

-- Índice parcial: solo indexa subset de filas
CREATE INDEX idx_pedidos_pendientes ON pedidos(fecha)
WHERE estado = 'pendiente';

-- Índice UNIQUE
CREATE UNIQUE INDEX idx_clientes_email ON clientes(email);

-- Crear índice SIN bloquear escrituras (producción)
CREATE INDEX CONCURRENTLY idx_ventas_fecha ON ventas(fecha);
\end{lstlisting}

\begin{lstlisting}[caption={EXPLAIN ANALYZE --- verificar uso de índice}]
-- Sin índice: Seq Scan
EXPLAIN ANALYZE
SELECT * FROM empleados WHERE salario > 80000;
-- Seq Scan on empleados (cost=0..520 rows=15)
-- Execution time: 8.4 ms

-- Crear índice
CREATE INDEX idx_empleados_salario ON empleados(salario);

-- Con índice: Index Scan
EXPLAIN ANALYZE
SELECT * FROM empleados WHERE salario > 80000;
-- Index Scan using idx_empleados_salario
-- Execution time: 0.3 ms

-- GIN para búsqueda en JSONB
CREATE INDEX idx_datos_gin ON tabla USING GIN (datos_jsonb);
SELECT * FROM tabla WHERE datos_jsonb @> '{"activo": true}';
\end{lstlisting}

\begin{lstlisting}[caption={Índices y FK en PostgreSQL}]
-- PostgreSQL NO crea índice automático en FK
-- Sin este índice, DELETE en tabla padre hace Seq Scan en hijos
CREATE INDEX idx_empleados_id_depto ON empleados(id_depto);
CREATE INDEX idx_pedidos_id_cliente ON pedidos(id_cliente);

-- Ver índices existentes
SELECT indexname, indexdef
FROM   pg_indexes
WHERE  tablename = 'empleados';
\end{lstlisting}
