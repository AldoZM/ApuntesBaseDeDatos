\chapter{Normalización}

\section[¿Por qué normalizar?]{\emj{🧠}~¿Por qué normalizar?}

La normalización es un proceso sistemático para eliminar redundancia de datos y anomalías de actualización.
Una tabla desnormalizada almacena el mismo dato en múltiples filas; cuando ese dato cambia, hay que actualizarlo en todos lados o la BD queda inconsistente.
Las tres anomalías clásicas son la señal de que el diseño necesita normalización.

\begin{teoriabox}{Las tres anomalías de la desnormalización}
\begin{itemize}
  \item \textbf{Anomalía de inserción:} no puedo registrar un departamento sin tener al menos un empleado en él
  \item \textbf{Anomalía de actualización:} cambio el nombre del departamento en una fila pero no en las demás; ahora hay inconsistencia
  \item \textbf{Anomalía de borrado:} al borrar al último empleado de un departamento, pierdo toda la información del departamento
\end{itemize}
La solución a las tres anomalías es separar entidades en sus propias tablas y usar FK para relacionarlas.
\end{teoriabox}

\section[Formas normales]{\emj{🧠}~Formas normales}

Las formas normales son niveles progresivos de diseño: cada una incluye a la anterior y agrega una restricción más.
En la práctica, 3NF es el objetivo mínimo; BCNF se alcanza en la mayoría de los diseños bien pensados de todas formas.

\begin{itemize}
  \item \textbf{1NF:} valores atómicos (sin listas/arrays en celdas), sin filas duplicadas, PK definida
  \item \textbf{2NF:} en 1NF + sin dependencias parciales (atributos dependen de \emph{toda} la PK compuesta, no solo parte de ella)
  \item \textbf{3NF:} en 2NF + sin dependencias transitivas (atributo no-clave no depende de otro atributo no-clave)
  \item \textbf{BCNF:} en 3NF + todo determinante es superkey (cubre casos extremos que 3NF no atrapa)
\end{itemize}

\begin{tipbox}{¿Hasta qué forma normalizar?}
3NF es el estándar mínimo para bases de datos transaccionales (OLTP).
Para bases analíticas (OLAP, data warehouses), a veces se \emph{desnormaliza} intencionalmente (star schema, snowflake) para reducir joins costosos en queries de millones de filas.
\end{tipbox}

\section[Dependencias funcionales]{\emj{🧠}~Dependencias funcionales}

Una dependencia funcional $X \rightarrow Y$ significa: conocer el valor de $X$ determina unívocamente el valor de $Y$.
Identificar dependencias funcionales es el mecanismo formal para detectar violaciones a 2NF y 3NF.

\begin{itemize}
  \item Si \textbf{PK = \{A, B\}} y existe $A \rightarrow C$ (C no depende de B) → dependencia \textbf{parcial} → viola 2NF
  \item Si existe no-clave $\rightarrow$ no-clave (por ejemplo \texttt{id\_depto} $\rightarrow$ \texttt{nombre\_depto}) → dependencia \textbf{transitiva} → viola 3NF
\end{itemize}

\begin{lstlisting}[caption={Tabla que viola 2NF y su corrección}]
-- VIOLA 2NF: PK=(id_pedido, id_producto) pero nombre_producto
--            depende solo de id_producto (dependencia parcial)
CREATE TABLE pedido_items_malo (
    id_pedido       INTEGER,
    id_producto     INTEGER,
    nombre_producto VARCHAR(100),
    cantidad        INTEGER,
    PRIMARY KEY (id_pedido, id_producto)
);

-- CORRECTO: separar producto a su propia tabla
CREATE TABLE productos (
    id     SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL
);

CREATE TABLE pedido_items (
    id_pedido   INTEGER,
    id_producto INTEGER REFERENCES productos(id),
    cantidad    INTEGER NOT NULL,
    PRIMARY KEY (id_pedido, id_producto)
);
\end{lstlisting}

\begin{lstlisting}[caption={Tabla que viola 3NF y su corrección}]
-- VIOLA 3NF: id_depto -> nombre_depto (dependencia transitiva)
CREATE TABLE empleados_malo (
    id_empleado  SERIAL PRIMARY KEY,
    nombre       VARCHAR(100),
    id_depto     INTEGER,
    nombre_depto VARCHAR(80)
);

-- CORRECTO: tabla separada para departamentos
CREATE TABLE departamentos (
    id     SERIAL PRIMARY KEY,
    nombre VARCHAR(80) NOT NULL
);

CREATE TABLE empleados (
    id       SERIAL PRIMARY KEY,
    nombre   VARCHAR(100),
    id_depto INTEGER REFERENCES departamentos(id)
);
\end{lstlisting}

\begin{entrevistabox}
\begin{enumerate}
  \item ¿Cuál es la diferencia entre 2NF y 3NF?
  \item ¿Cuándo desnormalizarías intencionalmente una tabla?
  \item Identifica la forma normal: \texttt{(orden\_id, producto\_id, categoria\_producto, cantidad)} con PK=(orden\_id, producto\_id).
\end{enumerate}
\end{entrevistabox}
